# /short

Everything runs from the repo root `/Users/a1/DEV/elementors-marketing`. Tools are plain Python 3, run them with `python3 -I`. Palmier Pro must be running; the game repo is `/Users/a1/DEV/pwn-zz`.

## Arguments

- `/short <name|path>` — build the short for `scenarios/<name>.md`.
- `/short voices` — list the ElevenLabs voices on the account: `python3 -I tools/tts.py --voices`. Stop there.
- `/short rerender <name>` — force a new Godot render even if one exists.
- `--export` — also export `exports/<name>.mp4` at the end.
- `--voice <name>` — override the scenario voice for this run (e.g. a premade voice when the library voice is not allowed by the plan).
- `/short <name> --variants` — also build every `scenarios/<name>__*.md` that has `base: <name>`: same render, own voice, plan and timeline.

## A/B variants

A scenario with `base: <other>` in its frontmatter is an A/B variant written by `/scenario`: identical beats, different first line, 0:00 caption and button. Never render it. Require `renders/<base>/<base>.cursor.json` (render the base first if missing), then run steps 3-5 for the variant by its own name: `tts.py` writes `vo/<variant>/`, `align.py` reads the base render and writes `renders/<variant>/plan.json`, `palmier_build.py` makes the timeline `<variant> 9x16`. Report both timelines side by side so the user can compare the hooks.

## Steps

1. **Parse.** `python3 -I tools/scenario.py scenarios/<name>.md --beats` and `python3 -I tools/scenario_lint.py scenarios/<name>.md` (estimates only; a WARN about a slow-build punch is fine, a timing WARN means the render will push a line late). Check that every beat with a voice line has an `at:` marker that the harness will produce (`beat:N` once the harness supports `mark`, or a legacy marker such as `impact`, `warmup`, `drop:<element>`, `star_up`). Scenario format is in the docstring of `tools/scenario.py` and in `docs/PIPELINE.md`.

2. **Render** when `renders/<name>/<name>.cursor.json` is missing or `rerender` was asked:
   ```
   python3 -I tools/scenario.py scenarios/<name>.md --harness > /Users/a1/DEV/pwn-zz/tools/scenarios/shots/<name>.json
   cd /Users/a1/DEV/pwn-zz && SHOT_MOVIE_ROOT=/Users/a1/DEV/elementors-marketing/renders tools/shot_movie.sh <name>
   ```
   Run the render in the background (it takes minutes: ~1 min per 10 s of footage, plus warm-up). While it runs, do step 3. When it finishes, confirm the mp4 probes with ffprobe and that the markers in the cursor json cover every beat's `at`. If a marker is missing, the harness scenario is wrong: fix the scenario, not the plan.

3. **Voice.** `python3 -I tools/tts.py scenarios/<name>.md [--voice X]`. One file per beat in `vo/<name>/beat_<n>.mp3` with word timings in `beat_<n>.words.json`; unchanged lines are cached. If the API answers `402 paid_plan_required`, the voice is a library voice and the plan does not allow it over the API: tell the user and either rerun with a premade voice (`--voice liam`, `--voice harry`) or let them drop files generated by hand at `vo/<name>/beat_<n>.mp3` (word timing then falls back to proportional). A single hand-made file with every line: find the pauses with `ffmpeg -af silencedetect=noise=-45dB:d=0.1`, check quiet lines (a whispered "...wait." sits near -30 dB) with a per-50 ms RMS pass, cut with `atrim` + `asetpts` + short fades, and write `beat_<n>.words.json` through `tts.words_proportional` with `digest: hand-cut <date>` so a later `tts.py` run does not overwrite the cut (it would fail on the library voice anyway).

4. **Align.** `python3 -I tools/align.py scenarios/<name>.md` writes `renders/<name>/plan.json` and prints beat frames, voice placement and total length. Read the warnings. Rules it applies: clip starts at the `warmup` marker; a voice line before a punch beat ends 5 frames before that punch; a punch beat's line starts 60 frames (1 s) after the punch, because a reaction that fires on the same frame as the roll, merge or stat reveal reads as scripted (`lead:` overrides it per beat); if a line would start before frame 0, a nearest-upscaled still of the first clean frame holds the opening; camera follows the cursor at 1.45x from shortly after the first move to the last drop, punches to 1.95x on `punch` beats, rests at 1.4x; a beat with only `wander` and a `focus:` frames that region instead of following (keep the cursor on a unit and set `focus: tooltip` to show its tooltip); the segment before a punch ends 20 frames early so the camera glides to the punch target in one move; after a punch the camera holds until the cursor has moved and settled, then follows.

5. **Build.** `python3 -I tools/palmier_build.py renders/<name>/plan.json [--export exports/<name>.mp4]`. It opens `palmier/ELEMS.palmier`, creates a timeline `<name> 9x16` (suffix `v2`, `v3` when the name exists), places the render, keyframes, hold still, voice clips, captions, and names the tracks. The export, when asked, waits for the job and prints the result.

6. **Verify in Palmier through MCP** (the script's session is separate, so first `manage_project open` with the same path in this session): `inspect_timeline` on each beat frame from the plan plus 6 evenly spaced frames. Check: no black frames at the start, punch centered on the unit, captions legible and not covering the action, the last frame not cut mid-motion. Fix small things directly with the MCP tools (`update_text`, `set_keyframes`, `move_clips`); fix anything structural in the scenario or in `tools/align.py` and rebuild, so the next short benefits.

7. **Report** in chat: timeline name, length, what to check by ear (voice vs game audio balance), export path if any. Do not export unless asked.

## Scenario cheat sheet

- Actions per beat, `;`-separated: `idle <s>`, `wait <s>`, `wander <s> r<px>`, `drift <dx>,<dy>`, `hover <target> [hold]`, `click <target>`, `drag <from> -> <to> [hold]`, `battle hold=<s> speed=<x>`, `summary focus=dps:<slot> hold=<s>`.
- Targets: `board:N`, `bench:N`, `stash:N`, `shop:N`, `recap:N` (summary row), `board:bare` (first bare 1★), `board:best`, `board:any`, `board:empty`, `node:%UniqueName`.
- Beat options in braces: `at: <marker>` (default `beat:N`; use `impact`, `drop:<el>`, `star_up`, `summary:focus`, `battle_end` when the beat should land on a game event), `punch`, `focus: <target|region>` (regions: shop, board, synergies, bench, stash, dice, battle, roll, gold, level, hp, tooltip), `zoom: <x>`, `align: left|center|right` (which end of a wide focus rect to frame, use `right` for summary numbers), `lead: <frames>`, `anchor: start|end`.
- Voice line length must fit the beat: the harness does not wait for speech. If align.py prints "voice pushed N frames late", add idle time to that beat in the scenario and rerender.
- Shop cards: `offer: {"kind": "echo_2star", "unit": "reptile", "element": "fire", "stars": 2}` arms the bonus slot; the card appears on the next refresh the scenario triggers (`click node:%RerollButton`), with the reveal FX. A missing `star_up` after the buy means the gold did not cover it or the merge landed on the bench.
- Real player boards: `board: supabase`, `stage: [2, 3]`, `pick: random|<build id>`, `require_bare: true`, `min_units: 3`, `exclude: [ids]`. The chosen build id lands in cursor.json and plan.json as `source_build`; `SHOT_BUILD=<id>` before shot_movie.sh reproduces it, `SHOT_PICK_SEED=<int>` makes a random pick repeatable only for the same snapshot cache; after a refetch, pin with `SHOT_BUILD`. Snapshots come from `pwn-zz/build/player_snapshots.json` (refresh with `tools/builds_run.sh --refetch` in pwn-zz).
- `camera: wide` in the frontmatter frames the whole scene (zoom 0.5 by default, `zoom:` per beat in the same units, above 1 is a close-up) and fills the bands above and below with darkened mirrored copies of the render.
- Battle beats: use PvE rounds (round 8 = Stage 2-3 PvE) until PvP opponents are pinned. A fight is ~39 s at speed 1; set `speed=4..6`.
- Renders queue on a lock in pwn-zz; two renders never run at once.

## Conventions

- Captions: Poppins-Bold 60 uppercase, black outline 8, yellow highlightPop, y 0.72, max 3 words. Defined once in `tools/palmier_build.py`.
- Shorts look like stream clips: no end card, no "free demo" plate, no AI webcam. Voiceover only.
- `tools/tts.py` sends all-caps words capitalized (eleven_v3 spells "THREE" letter by letter) and restores the caps in the word timings for captions. Library voices need a paid plan; `liam` and `harry` are premade.
- `voices.json` is a cache maintained by `tools/tts.py`; never ask the user to edit it. `voice:` in a scenario accepts a short name, an ElevenLabs voice name, or a raw voice id.
- Secrets live in `.env` (`ELEVENLABS_API_KEY`), never in the repo.
- Renders are deterministic: same scenario, same frames. A changed scenario needs a rerender; a changed voice line only needs steps 3–5.

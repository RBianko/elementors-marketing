# /short

Everything runs from the repo root `/Users/a1/DEV/elementors-marketing`. Tools are plain Python 3, run them with `python3 -I`. Palmier Pro must be running; the game repo is `/Users/a1/DEV/pwn-zz`.

## Arguments

- `/short <name|path>` — build the short for `scenarios/<name>.md`.
- `/short voices` — list the ElevenLabs voices on the account: `python3 -I tools/tts.py --voices`. Stop there.
- `/short rerender <name>` — force a new Godot render even if one exists.
- `--export` — also export `exports/<name>.mp4` at the end.
- `--voice <name>` — override the scenario voice for this run (e.g. a premade voice when the library voice is not allowed by the plan).

## Steps

1. **Parse.** `python3 -I tools/scenario.py scenarios/<name>.md --beats`. Check that every beat with a voice line has an `at:` marker that the harness will produce (`beat:N` once the harness supports `mark`, or a legacy marker such as `impact`, `warmup`, `drop:<element>`, `star_up`). Scenario format is in the docstring of `tools/scenario.py` and in `docs/PIPELINE.md`.

2. **Render** when `renders/<name>/<name>.cursor.json` is missing or `rerender` was asked:
   ```
   python3 -I tools/scenario.py scenarios/<name>.md --harness > /Users/a1/DEV/pwn-zz/tools/scenarios/shots/<name>.json
   cd /Users/a1/DEV/pwn-zz && SHOT_MOVIE_ROOT=/Users/a1/DEV/elementors-marketing/renders tools/shot_movie.sh <name>
   ```
   Run the render in the background (it takes minutes: ~1 min per 10 s of footage, plus warm-up). While it runs, do step 3. When it finishes, confirm the mp4 probes with ffprobe and that the markers in the cursor json cover every beat's `at`. If a marker is missing, the harness scenario is wrong: fix the scenario, not the plan.

3. **Voice.** `python3 -I tools/tts.py scenarios/<name>.md [--voice X]`. One file per beat in `vo/<name>/beat_<n>.mp3` with word timings in `beat_<n>.words.json`; unchanged lines are cached. If the API answers `402 paid_plan_required`, the voice is a library voice and the plan does not allow it over the API: tell the user and either rerun with a premade voice (`--voice liam`, `--voice harry`) or let them drop files generated by hand at `vo/<name>/beat_<n>.mp3` (word timing then falls back to proportional).

4. **Align.** `python3 -I tools/align.py scenarios/<name>.md` writes `renders/<name>/plan.json` and prints beat frames, voice placement and total length. Read the warnings. Rules it applies: clip starts at the `warmup` marker; a voice line before a punch beat ends 5 frames before that punch; a punch beat's line starts 12 frames after the punch; if a line would start before frame 0, a nearest-upscaled still of the first clean frame holds the opening; camera follows the cursor at 1.45x from shortly after the first move to the last drop, punches to 1.95x on `punch` beats, rests at 1.4x.

5. **Build.** `python3 -I tools/palmier_build.py renders/<name>/plan.json [--export exports/<name>.mp4]`. It opens `palmier/ELEMS.palmier`, creates a timeline `<name> 9x16` (suffix `v2`, `v3` when the name exists), places the render, keyframes, hold still, voice clips, captions, and names the tracks. The export, when asked, waits for the job and prints the result.

6. **Verify in Palmier through MCP** (the script's session is separate, so first `manage_project open` with the same path in this session): `inspect_timeline` on each beat frame from the plan plus 6 evenly spaced frames. Check: no black frames at the start, punch centered on the unit, captions legible and not covering the action, the last frame not cut mid-motion. Fix small things directly with the MCP tools (`update_text`, `set_keyframes`, `move_clips`); fix anything structural in the scenario or in `tools/align.py` and rebuild, so the next short benefits.

7. **Report** in chat: timeline name, length, what to check by ear (voice vs game audio balance), export path if any. Do not export unless asked.

## Conventions

- Captions: Poppins-Bold 60 uppercase, black outline 8, yellow highlightPop, y 0.72, max 3 words. Defined once in `tools/palmier_build.py`.
- Shorts look like stream clips: no end card, no "free demo" plate, no AI webcam. Voiceover only.
- `voices.json` is a cache maintained by `tools/tts.py`; never ask the user to edit it. `voice:` in a scenario accepts a short name, an ElevenLabs voice name, or a raw voice id.
- Secrets live in `.env` (`ELEVENLABS_API_KEY`), never in the repo.
- Renders are deterministic: same scenario, same frames. A changed scenario needs a rerender; a changed voice line only needs steps 3–5.
